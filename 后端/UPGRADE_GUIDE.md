# WildAPI 版本升级指南（数据位于 /opt/WildAPI）

> 适用场景：服务器上已运行 WildAPI，需要升级到新版本代码。
> 所有数据保存在 `/opt/WildAPI/`，升级过程**不删除任何数据目录**，
> 全程通过管理菜单操作，无需复杂命令。

---

## 一、升级流程总览

```
备份数据库(菜单7) → 停止服务(菜单4) → 替换代码 → 一键部署(菜单1，自动迁移) → 验证(菜单2)
```

> 配好 GitHub Actions 的四个密文后（见仓库 README「GitHub 自动部署」），
> 上面这套可以压成一次点击：Actions → deploy-server → Run workflow。
> 它会下载 Release 里的 `WildAPI.tar.gz`、备份现有代码、续用原 `.env` 再重新部署。
> 本文下面几节保留，用于手动操作或排障。

---

## 二、详细步骤

### 步骤 1：备份数据库

```bash
cd /opt/WildAPI/后端/docker
./wildapi.sh
```

菜单输入 **7**（备份数据库），备份保存到 `/opt/WildAPI/backups/`。
**建议同时把备份文件下载到本地**（宝塔 → 文件 → 下载）。

### 步骤 2：停止服务

菜单输入 **4**（停止服务）。数据目录不受影响。

### 步骤 3：替换代码（宝塔文件操作）

1. 上传新版 `WildAPI.tar.gz` 到服务器并解压到临时目录（如 `/opt/WildAPI-new`）
2. 宝塔 → 文件，进入 `/opt/WildAPI/`：
   - **删除** `后端` 和 `前端` 两个代码目录
   - **不要动** `mysql`、`redis`、`backups`、`logs` 这些数据目录
   (迁移脚本一律取自新代码里的 `后端/migrations`，`$DATA_DIR/migrations` 旧副本已不再使用)
3. 把 `/opt/WildAPI-new/后端` 和 `/opt/WildAPI-new/前端` 移动（剪切粘贴）到 `/opt/WildAPI/`

### 步骤 4：重新部署

```bash
cd /opt/WildAPI/后端/docker
chmod +x wildapi.sh deploy.sh uninstall.sh
./wildapi.sh
```

菜单输入 **1**（一键部署 / 更新），脚本自动：
- 复用 `/opt/WildAPI/mysql` 中的现有数据库
- 构建新版镜像
- 启动服务
- **依次执行 后端/migrations 下全部幂等迁移脚本 (当前 9 个)**，自动补齐旧库缺失的表和字段
  迁移失败不再被当成"表已存在"忽略：deploy.sh 会打印错误并以非 0 退出

### 步骤 5：验证

菜单输入 **2**（查看服务状态），确认 4 个容器全部 Up，然后：

- 浏览器访问前端，用原账号 SSO 登录
- 管理员查看供应商列表，确认密钥显示正常（能解密说明 `ENCRYPTION_KEY` 正确）
- 菜单 **6** 查看后端日志，确认无报错

## 三、重要提醒

### 3.1 密钥一致性

服务器上已有的 `docker/.env` 不要覆盖：数据包不再附带 `.env`（凭据不随包扩散），
升级时只替换 `后端/`、`前端/` 代码目录，下列配置必须与升级前保持一致：

- `ENCRYPTION_KEY` — 否则无法解密已存的供应商密钥和用户 API Key
- `JWT_SECRET` — 不一致仅导致现有用户需重新登录
- `SSO_CLIENT_ID` / `SSO_CLIENT_SECRET` — 否则 SSO 登录失败

### 3.2 WildAccount ID 格式（迁移 005）

新版要求 `users.wildaccount_id` 为 **UUID 字符串**（认证中心新标准）。
迁移脚本会自动转换列类型，**不删除数据**，但注意：

- 若旧库中该列存的是数字格式（旧认证中心），这些用户下次 SSO 登录时
  会以新 UUID 创建新记录（角色默认 user、余额 0）
- 处理方式：用户登录后，管理员在后台补余额、调角色即可
- 若旧库已在用 UUID，则完全无影响

### 3.3 回滚方案

升级后如出现严重问题：

1. 菜单 **4** 停止服务
2. 恢复代码：把升级前保留的旧版 `后端`/`前端` 目录移回 `/opt/WildAPI/`
3. 旧目录重新执行 `./wildapi.sh` → 菜单 **1** 部署
4. 数据库问题则用步骤 1 的备份文件恢复

> 迁移脚本均为幂等写法（`CREATE TABLE IF NOT EXISTS` 等），
> 多数情况只需回滚代码，无需恢复数据库。
